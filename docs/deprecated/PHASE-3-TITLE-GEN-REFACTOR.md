# Phase 3 — Server-Side Title Generation Refactor

**Branch:** `feature/phase3-title-gen-server`
**Status:** ✅ Complete
**Depends on:** Story 3.8 complete (it is — `feature/phase3-pending-thread` merged)

---

## Why This Refactor Exists

The client-side title generation introduced in Story 3.8 has two compounding problems:

### Problem 1 — The sidebar never updates

`upsertThread` updates the in-memory store, but the sidebar is not reliably driven from it. The SSE `ThreadUpdated` global event that fires from `agent::run_inner` only carries `last_message`, not the new title. So the title generated by the client's `GET /api/threads/:id/generate-title` call never reaches the sidebar unless the page reloads.

### Problem 2 — The client-side timing dance is race-condition-prone

The current flow:

1. User sends first message → `POST /api/messages` → server returns user `Message`
2. Server spawns `tokio::spawn` → `agent::run()` starts in background
3. Client receives `201 Created`, `ChatView` sets `titleGenPendingRef = true`
4. Agent streams tokens via SSE → client shows streaming bubble
5. Agent finishes → fires `MessageComplete` SSE event
6. Client `useEffect` watches `isStreaming` for the `true → false` falling edge
7. Client fires a second HTTP call: `threadsApi.generateTitle(thread.id)`
8. Server runs LLM title gen, returns `{ title }`, client calls `upsertThread`

Step 3 seeds `titleGenPendingRef` before the first SSE token arrives. If the stream starts before `ChatView` has fully mounted — a realistic race on slow renders or fast agents — the ref is never set and title gen silently skips.

### The fix

Move title generation entirely to the server, triggered automatically after the first assistant reply is persisted. Broadcast a new `TitleUpdated` SSE event on the global stream. The client sidebar updates in real time with no second HTTP call and no timing logic.

## Proposed Architecture

### Server: Step 6.5 in `agent::run_inner`

After step 6 (persist assistant message) and before step 7 (emit SSE events), count messages in the thread. If this is the first assistant reply (total message count ≤ 2: one user + one assistant), run title generation and persist the result, then broadcast `GlobalEvent::TitleUpdated`.

```agent-deck/server/src/services/agent.rs#L270-290
// ── 6.5 First-message post-processing ─────────────────────────────────────
// Count total messages in this thread. If this is the first assistant reply
// (i.e. exactly 2 messages: 1 user + 1 assistant), run title generation,
// persist the result, and broadcast TitleUpdated so the client sidebar
// updates without a page reload.
let message_count: (i64,) = sqlx::query_as(
    "SELECT COUNT(*) FROM messages WHERE thread_id = ?"
)
.bind(thread_id)
.fetch_one(&state.pool)
.await?;

if message_count.0 <= 2 {
    // call services::title::try_llm_title(...)
    // UPDATE threads SET title = ? WHERE id = ?
    // broadcast GlobalEvent::TitleUpdated { thread_id, title }
}
```

### New `GlobalEvent::TitleUpdated` variant

Add to `GlobalEvent` in `copilot.rs`:

```agent-deck/server/src/services/copilot.rs#L57-62
TitleUpdated {
    thread_id: String,
    title: String,
},
```

### New `services/title.rs`

Extract `try_llm_title` out of `threads.rs` into a new shared service module so both `agent.rs` and `threads.rs` can call it without coupling the two route files to each other.

```agent-deck/server/src/services/title.rs#L1-10
// services/title.rs
// Shared LLM title generation logic.
// Called by:
//   - agent::run_inner (automatic, after first assistant reply)
//   - routes::threads::generate_title (manual/debug endpoint — see note there)
pub async fn try_llm_title(...) -> Option<String> { ... }
```

### `routes/threads.rs` — manual endpoint kept, marked deprecated

The `GET /api/threads/:id/generate-title` endpoint stays in place for manual and debug use. It is **no longer called by the client automatically**. Add a comment at the handler:

```agent-deck/server/src/routes/threads.rs#L1-5
// generate_title — manual/debug endpoint only.
// The client does NOT call this automatically. Title generation is driven
// server-side by agent::run_inner after the first assistant reply.
// This endpoint is intentionally kept for development and manual testing.
// Returns 503 Service Unavailable if called in production to discourage client use.
```

The handler returns `503 Service Unavailable` with a JSON body `{ "error": "Use server-side title generation. This endpoint is reserved for manual/debug use only." }`.

### `sse.rs` — dispatch `TitleUpdated`

Add a match arm in `global_stream`'s event dispatch for the new `TitleUpdated` variant. The SSE event name is `title_updated`. Payload:

```agent-deck/server/src/routes/sse.rs#L1-5
// GlobalEvent::TitleUpdated
// event: title_updated
// data: { "thread_id": "...", "title": "..." }
```

### Client: `useSseStore.ts` — add `title_updated` handler

In `connectGlobal`, add a handler for `title_updated` that calls `upsertThread` with the new title. This is the single source of truth for sidebar title updates going forward.

### Client: `ChatView.tsx` — remove all client-side title gen logic

The following are deleted entirely:

- `titleGenPendingRef`
- `prevIsStreaming` ref
- `isFirstSend` prop (and its declaration in the component signature)
- The `useEffect` that watches `isStreaming` for the falling edge
- The `threadsApi.generateTitle(...)` call

### Client: `useThreadStore.ts`

Remove any `isFirstSend` tracking or state that exists solely to support the client-side title gen flow.

### Client: `titleGen.test.ts`

Delete the file. It tests the now-dead client-side flow. No replacement test is needed here — the server-side path is covered by integration tests.

### Client: `App.tsx`

Remove the `isFirstSend` prop pass-through if it exists anywhere in the component tree.
